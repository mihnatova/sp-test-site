Script installation detection — test scenarios

Fixtures for QA of the SP script installation check (ADO #8667). Each scenario is a separate page so it can be registered as its own domain in test-v2.

#ScenarioHow the tag is deliveredExpected
01directStatic tag, first script in <head>CorrectlyInstalled
02gtmGoogle Tag Manager container onlyunder test
03dynamiccreateElement on DOMContentLoadedunder test
04noneNot present at all (negative control)NotInstalled
05delayedsetTimeout 4000 msunder test
06idonlyDomain ID in body text, no script at allfalse-positive control
Before testing: register each page URL as its own domain in test-v2, then run ./set-id.sh <scenario> <domainId> from the repo root and push, so the page carries the ID the detector will look for. Scenario 02 also needs __GTM_CONTAINER_ID__ replaced with a real published container. Scenario 04 takes no ID.

Why 03 and 05 assemble the script URL at runtime: the plain-HTTP pass returns early if the raw HTML contains either the domain ID or the SP script URL, and the browserless pass only runs when that first pass came back NotInstalled. Splitting both strings is what makes those two fixtures actually exercise browserless instead of short-circuiting before it.
